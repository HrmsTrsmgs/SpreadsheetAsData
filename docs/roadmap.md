## フェーズ6: 型付き読み書きコードの生成

- [x] `.xlsx`からテーブル定義を読み取る

- [x] 空白を含む文字列列を `string` として生成する
- [x] データ行があり空白だけの列を `string` として生成する
- [x] データ行がないテーブルから列プロパティを持たない行データクラスを生成する

- [x] ワークブック全体を表す読み取り型を生成する
- [x] 生成型から定義名とExcelテーブルへ書き戻す
- [ ] 生成元スキーマと実ファイルの不一致を検出する
- [x] 型名や列名の衝突を検出する
- [x] 生成コードのテストを追加する
- [x] 型付き読み書きのサンプルを追加する

生成元スキーマとの不一致については、生成Bookの `Open` で必要なシート、Excelテーブルとその列、ブックスコープとシートローカルの定義名の不足を検出するところまで実装・テスト済みです。
列の不足は、その列を利用するかどうかにかかわらず `Open` 時点でエラーにします。
また、生成元で単一セルだったブックスコープの定義名が、複数セルへ変わった場合も `Open` 時点で検出します。
これだけで値の型など、すべての不一致を検出できるわけではないため、項目全体は未完了としています。

- [ ] 後日のバージョンアップで、使用しない項目を明示する無視属性を検討する。マッピング対象と `Open` 時の不足検証との関係を含めて設計し、現時点では欠落を暗黙に許容しない。

コード生成APIは `Marimo.SpreadSheetAsData.CodeGeneration`、Visual StudioとMSBuildの連携は `Marimo.SpreadSheetAsData.Build` で提供します。
通常の利用では、実行時APIとコード生成機能をまとめた `Marimo.SpreadSheetAsData` を使用します。
対応型と空白の変換規則は、[型付き読み書き](typed-reading.md)を参照してください。

Stream版の `Save()` は元Streamを変更する前に拒否し、Close/Disposeでも保存しない。
Stream入力の編集結果は `SaveAs(path)` で出力できるが、Streamだけで出力まで完結するAPIは現行範囲に含めない。

## 初回公開後の候補

### 書き込み

- 行の追加
- 行の挿入
- 行の削除
- テーブル行の追加
- テーブル範囲の拡張と縮小

### 大規模ファイル

- OpenXmlReaderを使用した逐次読み取り
- OpenXmlWriterを使用した逐次出力
- ファイル全体をDOMへ展開しない変換
- 差分を保持して保存時に統合する編集モデル

### Excel機能

- 書式
- 数式
- 構造化参照
- 集計行
- フィルター
- テーブルスタイル
- シートや範囲の複製

初回公開後も、Excelの全機能対応そのものは目標にしません。

SpreadsheetAsDataのデータ操作として意味のある機能から追加します。
