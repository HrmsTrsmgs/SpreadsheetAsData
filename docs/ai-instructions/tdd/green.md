# Green: 今回のRedを直接通す

`common.md` とこの文書だけを工程指示として読む。今回のRedテスト、確認済みの失敗、確定した外部契約、必要な現行コード、関連既存テスト、ビルド・テスト方法、必須制約を受け取る。要求一覧全体、将来候補、未採用API案、Redの設計議論、Refactor方針、過去の工程履歴は読まない。

現在の失敗の直接原因を確認し、最初に見つかった直接的な実装を試す。定数返し、特殊ケース、一時的な重複や不格好なコードは、現在の契約と既存契約を満たすなら許容する。明らかな既存実装があるのに、わざと直書きへ置き換える必要はない。

将来の入力、未要求の失敗条件・例外・並行性・破棄時保証・再試行・復旧、拡張性、共通化、責務整理、抽象化を先取りしない。アルゴリズムの一般的正当性やミスの注意深い目視確認をGreen内で追求せず、自動テストで現在の失敗と必要な回帰を素早く確かめる。失敗したらその結果を修正する。既存契約を壊さない確認は省略しない。

テストの期待値、検証対象、外部契約を実装へ合わせて変更しない。テストの削除、Skip化、実行対象からの除外でGreenにしない。未決定の外部契約が不可欠なら停止し、進行役が承認した新仕様を同じGreenへ追加する扱いにはしない。既存の `Skip` 対象へ波及しそうな共通処理や、対象外のテストデータ整理が必要なら着手前に報告する。

仕様変更で他のテストが失敗した場合は、新契約に合わせるべき期待か、維持すべき既存契約の回帰かを区別する。前者は新しいRedの対象として扱い、後者は実装を修正する。現在の実装結果へ期待値を追従させない。

対象と必要な回帰テストが通ったら、今回のGreen差分を一度だけ確認する。使われないコード、試行の残骸、未要求の分岐・例外処理・将来対応、デバッグ用ログや補助処理、二重実装がないかを見る。不要コードを除いたら影響するテストを再実行する。より短い別アルゴリズムの探索や共通化はここで行わない。

終了時は未コミット差分を残し、テスト結果と確認対象を進行役へ返す。ユーザーがIDE等で確認し了承する前にGコミットを作らない。Refactorへ続行せず、このGreenコンテキストを終了する。
