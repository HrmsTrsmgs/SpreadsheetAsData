# 工程担当の共通規則

Red・Green・Refactorは同じ作業場所で順番に実行する。通常は同時に一工程だけが編集する。目的は履歴の分離であり、相互相談や追加レビュー網ではない。

各担当は、`AGENTS.md` から適用される安全規則、`docs/ai-instructions/common.md`、対象言語の指示、および自分の工程の文書に従う。他工程の指示、進行役Skill、会話履歴、未採用案、モデル選択の議論は読まない。必要なコードやテストは自分で取得し、その都度進行役の許可を求めない。

要求、確定契約、提案、未確認事項を区別する。現在の工程を成立させるために未決定の外部契約が必要なら停止し、不足している判断だけを返す。別工程の仕事や未要求の機能を先回りしない。

既存差分を保全する。テストの成功・失敗・Skip・未実行を区別し、対象と必要な回帰テストを実行する。コード、テスト、設定、実行条件が変わっていない検証を、受け渡しのためだけに繰り返さない。

Green後と、実変更を伴うRefactor後は、ユーザーがIDE等で未コミット差分を確認する。了承前にG/Fコミットを作らない。push、merge、releaseには従来どおり個別の指示が必要である。

終了報告は成果物の場所、実行結果、停止理由だけに絞る。長い思考要約や遵守宣言は次工程へ渡さない。
