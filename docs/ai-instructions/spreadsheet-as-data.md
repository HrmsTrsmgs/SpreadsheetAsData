# SpreadsheetAsData固有作業指示

この文書は、SpreadsheetAsDataリポジトリに固有の目的、設計、公開準備、周辺運用を定義する。

## プロジェクトの目的

SpreadsheetAsDataを、第三者がビルド、テスト、利用、レビューできるC#/.NETライブラリとして整備する。

機能数を増やすことより、次を優先する。

* 利用側コードの簡潔さ
* 変更箇所の局所化
* 責務分離
* 依存関係の整理
* 低水準APIの抽象化
* 業務的な変換規則の集約
* 公開APIの理解しやすさ
* テスト可能性
* 自動テストによる振る舞いの確認
* READMEから目的、使用方法、制約を理解できること

## 設計と公開API

* 詳細な設計方針は `docs/design.md` を参照する。
* 公開API、依存パッケージ、ビルド構成、永続化形式を変更する前に、理由と影響範囲を確認する。
* 公開APIの変更が必要な場合は、既存利用コード、テスト、サンプルへの影響を確認する。
* SDKや低水準APIの都合を、そのまま公開APIの責務にしない。
* テストのためだけに型やメンバーの公開範囲を広げない。
* 当面はv0系として、API互換性よりも使いやすい設計への修正を優先する。
* 互換性を崩す可能性がある場合は、READMEや設計文書の現在の公開方針と整合するか確認する。

## C#版とRuby版

* Ruby版のテストは、Ruby側のコードまたはテストデータを変更した場合、またはC#側の変更をRuby側へ同期した場合に実行する。
* C#側だけの変更でRuby側へ反映していない場合は、Ruby版のテストを毎回実行しなくてよい。
* C#版とRuby版で共有するテストデータを変更する場合は、意図した同期かどうかを確認する。
* Ruby版は今回の主対象ではないが、共有テストデータを壊さない。

## テストデータ

* テストデータは、テストの意図が読み取れる最小限の内容にする。
* オールインワンの巨大なExcelファイルで無関係な仕様をまとめて確認しない。
* 既存のテストデータ整理方針がある場合は、それを優先する。
* Excelファイルを開いたことでOpen XML内部の名前空間宣言や属性順序だけが変わることがあるため、値や仕様に関係する差分か確認する。
* Excel保存ノイズらしいバイナリ差分は、明示的な理由なしにコミットしない。

## READMEと公開準備

* READMEと公開準備の観点は `docs/roadmap.md` を参照する。
* READMEには、実装とテストから確認できる内容だけを書く。
* 未実装機能を実装済みのように書かない。
* READMEは、初めて使う人が食いつきやすい順に並べる。
* 高レベル操作を先に示し、必要に応じて低レベルAPIへ進める。
* Visual Studioでの使い始め、CLIでの使い始め、NuGetパッケージ、サンプルデータの導線を保つ。
* デモ動画をREADMEから案内する場合は、GitHub上での実際の挙動を確認する。
* GitHubの通常リンクでダウンロード動作になる動画は、リンク文言にダウンロードと明記する。
* 動画をGitへ直接コミットすると差し替えごとに履歴が太るため、頻繁に更新する動画はGitHub Releasesなどの外部アセット化を検討する。

## APIドキュメントとPages

* C# APIドキュメントは、正規のXMLコメントから生成する。
* APIドキュメント生成は、ローカルで確認できる手順を優先する。
* GitHub Pages公開は、ローカル生成と内容確認の後に行う。
* READMEにPages手順を書く場合は、誰が実行するかではなく、実際に保守できる操作として書く。

## NuGetとVisual Studio連携

* NuGet公開準備では、READMEの記述、パッケージ内容、ローカル確認、実際の公開順序を取り違えない。
* NuGetに公開しないと確認できないVisual Studio連携は、公開前に可能なローカル確認と、公開後の手動確認を分けて扱う。
* Visual Studio上の見え方を変更する場合は、ユーザーの手元で表示確認してから公開作業を進める。
* APIキーや公開用トークンは出力、保存、コミットしない。

## コミット前処理

* コミット前に `scripts/Normalize-ChangedTextFiles.ps1 -IncludeUntracked` を実行し、変更中のテキストファイルの改行コードとBOMを機械的に正規化する。
* 正規化後に差分を再確認する。
* バイナリファイルや動画など、正規化対象外のファイルはサイズと目的を確認してからコミット対象に含める。
